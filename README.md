# 假期方案详情原型（业务精简版）

## 版本边界

- 本目录是从“02-假期方案详情原型”复制出的业务精简版；完整版作为备份保留，不在本轮修改。
- 页面保留方案头、休假配置、年假配置、调休假配置、病假配置和公出/出差方案的现有骨架。
- 当前重点是统一国内假别的配置方式，示例覆盖年假、调休假、事假、病假、婚假、产检假、产假、流产假、难产假、哺乳假、陪产假、丧假和福利假。
- 年假、调休假和病假以 OEHR 现有配置逻辑为底稿，本轮主要调整信息分组、标题和页面样式；除已确认的国内适配项外，不新增、不删除、不改变原有业务枚举。

### 年假、调休假、病假的改版边界

- 年假仍按“年假生成规则、年假结转规则、年假结算规则”组织；只有额度计算支持“标准配置、公式配置”，额度生成资格始终直接使用结构化条件。
- 调休假按“调休生成规则、调休结转规则、调休结算规则”组织；加班来源、转换比例、有效期、扣减顺序和离职处理仍沿用 OEHR。
- 病假按“病假生成规则、病假有效期规则、病假结算规则”组织；原有计算规则、余额有效期、扣减顺序、额度结算和离职处理保持不变，不把其他假别的资格或周期模型套到病假中。
- 跨年度转正补发、国内假别时长条件和自由班次按天折算属于已确认的国内适配项，需与 OEHR 原有字段分组展示，不能反向改写原规则。

## 方案状态、编辑与版本

- 假期方案状态只有“启用、停用”，不设置草稿态和发布动作。
- 点击“新增”进入空白编辑页；保存并通过完整性、范围冲突和额度配置校验后，生成方案并默认启用。保存前系统中不存在方案记录。
- 从方案列表点击“编辑”直接进入编辑态；启用方案保存成功后立即生效，并自动生成下一版本。
- 编辑页底部只保留“取消、保存”，并固定悬浮在浏览器底部，滚动长配置页时始终可见；正文预留底部空间，不遮挡最后一组配置。存在未保存修改时离开页面，系统必须二次确认。
- “人员类型、员工类型”使用可多选的枚举下拉。展开后选择具体枚举，收起后展示选中值或选中数量，适配枚举较多的场景。
- 启用方案展示“停用”，停用方案展示“启用”。启停动作均保留操作人、操作时间和影响范围记录。
- 停用只阻止新的休假申请继续命中该方案，不修改历史版本、历史休假单、审批中单据和已生成额度。
- 停用前检查命中员工是否仍有其他启用方案可用；存在无方案员工时阻止停用。重新启用前再次检查配置完整性、适用范围冲突和专属额度配置。
- 当前版本可点击查看历史版本；历史版本以当前版本号下方的轻量卡片展示，包含版本、最近修改人和最近修改时间。历史版本只读，不直接覆盖当前配置。
- 点击“复制”后进入新增方案页面，继承原方案的适用范围和各页签配置，但方案名称必须留空，由业务人员重新填写；保存后才生成新方案、版本`00001`并默认启用。不得自动使用“原方案名称－副本”作为新方案名称。
- 点击某一历史版本后进入完整方案详情，只读展示该版本的方案信息、休假配置及专属额度配置；只保留页签切换、规则说明和“返回”，不提供编辑或保存入口。
- 本期不支持提前保存未来生效政策。后续如增加未来生效能力，需要另行设计生效时间和新旧规则判断日期。

方案列表展示：方案名称、当前版本、划分区域、人员类型、员工类型、状态、创建人、创建时间、更新人、更新时间和操作；不展示“包含假别”。启用状态操作为“编辑、复制、停用”，停用状态操作为“编辑、复制、启用”。

列表操作区位于方案列表标题右侧，依次提供“导出、导出设置、新增”。“导出”仅导出当前查询结果，不包含历史版本；“导出设置”可选择方案名称、版本、适用范围、状态和创建/更新信息等列表字段。

## 统一配置结构

每种休假使用同一套四个一级信息块，内部用轻量小标题区分业务问题，不再为婚假、产检假等分别设计专属页面：

1. 基本设置：不再拆分内部小标题，直接连续展示休假类型、计量单位、是否带薪、单次最小时长、单次最大时长、时长计算方式、日最大时长和舍位字段。
2. 可休时长：下分“可休时长控制”和“可休时长使用方式”。前者从“按可用额度、按政策条件、按周期上限、不设置累计上限”四种方式中选择一种；后者决定已经取得的可休时长能否拆分申请。
3. 申请规则：申请资格、休假日期、申请间隔和前置假。
4. 材料与员工说明：附件要求和员工政策说明。

“休假日期范围”校验员工选择的休假开始、结束日期。本轮不在假期方案中单独配置补申请，后续由休假申请与考勤闭环统一处理。

“关联休假单”不作为假别配置字段。需要关联原休假单的场景，由休假申请单根据当前申请的假别控制是否展示关联休假单选择项，并保存员工选择的原休假单；本期假期方案不配置关联假别、原单状态等规则。

“可休时长控制”和“可休时长使用方式”属于同一一级信息块，但仍是两个独立字段：前者回答“员工累计最多可以休多少”，后者回答“已经取得的可休时长能否拆成多张休假单使用”，选项为“可分次申请、必须一次申请完”。

### 配置控件选择规范

- 固定、互斥且能完整平铺展示的 2～3 个短选项，默认使用轻量单选框，让配置人员直接看到并单击选择，不使用下拉框。
- 分段按钮只用于“标准配置／高级公式”等模式切换，或需要明显强调当前视图状态的场景；普通字段不使用大块按钮式选择。
- 当前休假配置中，计量单位、是否带薪、时长计算方式、舍位方式、可休时长使用方式，以及可休规则中的短选项均按此规范展示。
- 休假类型、业务字段、周期等动态或选项较多的枚举继续使用下拉；筛选器、表格高密度配置和句式内嵌配置也可保留下拉。
- 存在级联关系时，父级字段保持主行展示；只有命中父级选项后，才在其下方缩进展开子级配置。子级使用浅色背景和左侧引导线表达从属关系，不与父级选项平铺成同一级。
- 控件形态改变时，必须同步校验默认值、禁用或只读状态、联动显隐、表单取值和保存结果，不能只改页面样式。

## 关键业务口径

### 1. 计量单位

- 假别计量单位是申请时长和可休时长规则的唯一单位。
- 可休时长规则只填写数值，单位继承基本信息，不能在单条规则中再次选择。
- 单次最小时长、单次最大时长在小时制和天制下都按小时配置；天制使用这两个字段作为自由班次没有有效工作时长时的申请与扣减兜底。
- 所有带单位的录入项采用“数值输入框＋只读单位”，不允许员工在文本框中输入“1小时”“5天”等混合文本。

统一单位字典：

| 配置项 | 单位或选项 | 说明 |
|---|---|---|
| 假别计量单位 | 小时、天 | 申请时长和可休时长结果的唯一单位 |
| 单次最小/最大时长 | 小时 | 小时制和天制均固定为小时，用于单张申请校验及自由班次兜底 |
| 日最大时长、舍位基数 | 小时 | 固定单位 |
| 可休时长规则结果 | 继承假别计量单位 | 规则只填写数值 |
| 休假日期偏移 | 自然日、工作日、日历月、日历年 | 只计算日期边界，不扣减休假时长 |
| 同类休假间隔 | 小时、自然日、工作日、周、月 | 小时只对有明确起止时间的小时制假别开放 |
| 规则统计周期 | 工作日、自然日、自然周、自然月、自然年 | 表示重新统计时长或次数的周期 |
| 附件阈值 | 申请时长继承假别单位；日期跨度固定为自然日 | 自动展示 |

日历月、日历年按对应日历日期计算，不是把月、年拆成自然日逐日扣减。月末没有对应日期时取该月最后一天；闰年2月29日跨年时取次年2月最后一天。

### 2. 日最大时长与按天折算

- 小时制：日最大时长限制一天最多计入多少休假小时。
- 天制：员工按日期申请，每个可计入日仍计1天；生成考勤业务明细时，需要把该天转换成小时。
- 固定班次整日折算：取班次工作时长与假别日最大时长的较小值。
- 自由班次存在有效工作时长时：取班次工作时长与假别日最大时长的较小值。
- 自由班次工作时长为0时：使用假别日最大时长作为当天考勤小时的兜底值。
- 因此日最大时长在天制下仍保留，页面统一名称为“日最大时长”，单位固定为小时。

### 3. OEHR原字段承接

- `可休假条件（天）`不再保留独立输入框，迁移为申请资格条件：`截至申请日入职天数 ≥ N`；没有该限制时不配置此条件。
- `休假周期（天）`不再作为所有假别的必填字段；需要控制时开启“限制相邻两次同类休假的间隔”。小时制假别可选小时、自然日、工作日、周或月，天制假别不展示小时。系统比较本次休假开始时间与上一笔有效同类休假的结束时间。
- OEHR年假配置里的“天转换为小时数”只负责额度生成和账户记账，不代替本页的申请时长计算或按天考勤折算。

### 4. 可休时长控制

- 按可用额度控制：本次申请不能超过当前可用额度，适用于年假、调休假，以及明确启用额度管理的病假；额度生成、有效期、结转和结算仍在对应额度页签维护。
- 按政策条件确定可休时长：根据城市、孕周、亲属关系等政策条件返回对应时长，适用于婚假、产假、流产假、难产假、陪产假和丧假。
- 按周期设置可休上限：按工作日、自然月等周期控制时长或申请次数，适用于产检假、哺乳假。
- 不设置累计上限：不限制员工一共可以休多少，只校验单次时长、日期、材料和审批，适用于事假等场景。
- 按政策条件确定可休时长和按周期设置可休上限时，统一支持两种互斥配置方式：
  - 规则表：每条规则把“时长条件＋可休结果”放在一起配置，按从上到下的顺序匹配，命中第一条即返回；
  - 统一公式：一个公式同时表达判断条件与可休结果，最终只返回可休时长数值，单位继承假别计量单位。
- 规则表支持拖拽排序、复制、编辑和删除；系统按从上到下的顺序匹配，命中第一条即结束。
- 兜底规则必须由业务明确选择“其他情况”，最多配置一条；保存后由系统自动固定在规则列表最后且不可拖动。没有“其他情况”且申请未命中任何规则时，由休假申请页提示“未匹配到可休时长规则”并阻止提交。
- 流产假样例使用统一公式表达孕周条件和15天／42天结果，避免条件和结果分别维护。

难产假仍作为独立假别配置：难产假本身使用“按政策条件确定可休时长”计算天数。员工申请难产假时是否需要选择原产假单，由休假申请单交互控制，不在假期方案中配置；关联关系不改变产假单，也不参与难产假时长计算。

### 5. 字段来源

原型只允许规则读取已经存在并能稳定取得的数据：

- 员工档案：性别、婚姻状况、员工类型；
- 任职信息：转正状态、工作城市；
- 休假申请单：预产期、孕周、去世亲属身份、哺乳时段；
- 系统计算：截至申请日入职天数、连续工作月数、依据孕周换算的孕期阶段。

结婚登记日期、流产日期、实际生产日期等当前没有结构化来源的事实，不做成自动条件。需要时由审批人根据结婚证明、医疗证明等附件核验。

### 6. 孕周与流产假

- 员工按“周＋天”填写孕周，天数只允许0～6；系统换算成总天数后比较。
- 当前样例用16周0天表达“满4个月”的配置边界：未满时15天，达到后42天。
- 16周边界是可配置示例，正式上线前仍需由业务确认政策口径。
- 流产事实不要求员工填写流产日期，通过医疗附件和审批核验。

### 7. 附件

- 附件类型作为独立基础资料，通过左侧“附件类型”菜单进入独立列表页，支持按名称和状态查询、导出、新增、编辑及启停；假期方案中的休假配置只引用已启用的类型。
- 停用附件类型后不再用于新规则，历史规则中已经引用的类型继续保留，避免既有政策失真。
- 附件按规则表配置，每条规则明确“判断依据、什么时候需要、需要的附件类型”。
- 判断依据支持“所有申请”“本次申请时长”和“休假日期跨度”。前者每次申请触发；本次申请时长使用系统试算结果并继承假别单位；日期跨度按自然日计算。
- 点击“选择附件类型”打开可搜索的选择弹窗；规则列表只展示已选类型摘要，不在页面平铺全部类型。
- 选择多个附件类型时，可配置“全部提供”或“任意提供一种”，默认全部提供。
- 不在本轮配置材料补交方式、材料不符合时的系统处理，材料真实性和充分性由审批判断。

### 8. 三八妇女节假样例

- 作为独立休假类型由员工自行申请，计量单位为小时；单次最小、单次最大和日最大时长均为4小时。
- 采用“按周期设置可休上限”，时长条件和可休结果配置在同一条规则中：员工性别为女，且系统判断当年3月8日不是星期六或星期日时，每个自然年最多申请1次，每次4小时。
- 系统按日历星期判断3月8日是否为周末；即使当天属于调休补班日，只要是星期六或星期日，当年仍不可申请。
- 可选休假日期为当年3月8日至3月31日，超过3月31日不可申请。
- 本规则不建立妇女节假额度账户；未命中时长规则时，本年度不能提交该假别。

## 必填规则

始终必填：休假类型、计量单位、是否带薪、单次最小时长、时长计算方式、日最大时长和可休时长控制方式。

按条件必填：

- 小时制启用舍位时，舍位基数和舍位方式必填；
- 使用政策条件或周期控制时，至少配置一条完整可休规则；
- 开启申请资格、休假日期范围或同类休假间隔后，对应条件必须完整；
- 开启附件模块后至少配置一条规则；条件型附件规则必须填写判断数值，每条规则至少选择一种附件类型；
- 开启员工端政策说明后，说明内容必填。

## 交互说明

- 休假列表展示休假类型、计量单位、单次最小时长、单次最大时长、时长计算方式、日最大时长、舍位基数、舍位方式、可休时长控制和是否带薪；不展开资格、日期和使用要求。
- 可休时长配置统一提供“常规条件 / 高级公式”两种方式；常规条件维护规则表，高级公式维护一个完整公式。两种方式的结果单位都继承休假类型基本信息中的计量单位。
- 年假、调休假、病假页签分别提供启用开关；关闭后该页签内配置不可编辑，重新启用后恢复原配置。
- 休假配置列表不再单独占用一块查询区域；需要筛选的字段在表头点击筛选图标设置，当前生效的筛选项显示蓝色状态。
- 单一判断模块（如申请资格）采用两种交互：常规条件直接在页面增删修改；高级公式在独立弹窗中配置，保存后回到页面展示“高级公式已配置”的状态及判断结果，提供查看、修改和清除。引用字段不等于判断条件，因此不能拿字段名称代替公式结果。
- 可休时长属于“条件＋结果”的多条规则，新增或编辑后保存到规则列表。列表展示执行顺序、系统生成的时长条件摘要、可休结果和操作；摘要展示主要条件，悬浮时查看完整条件。
- 时长条件的设置方式采用普通单选项，不使用大面积选项卡；规则列表中的时长条件展示带虚线的简短摘要，直接悬浮或聚焦摘要文字即可查看完整条件关系、条件值或公式原文，不再额外放置问号。
- 规则列表的悬浮详情不受表格滚动边界裁切；所有规则类弹窗底部统一使用“取消 / 确定”，对象级新增编辑页面仍使用“取消 / 保存”。
- 四种可休时长控制方式采用业务化选项卡展示；“按可用额度控制”的维护位置收入字段问号提示。
- 规则结构由系统在保存时自动检查；正常时不展示成功提示，只在存在冲突时展示错误。
- 时长规则编辑不再设置“使用范围”。新增规则时必须明确选择“满足以下条件”或“其他情况”，不能再用空白条件隐式表达兜底。
- 简单条件使用结构化字段、判断符和值；多条条件支持“且/或”。只有标准条件无法表达时才使用公式。
- 高级公式提供“检查公式”和“规则试算”，并保存“未检查／检查未通过／检查通过”状态；内容修改后状态自动回到“未检查”。未通过检查的公式可保留在当前编辑页面；新增、复制及启用方案不能使用该公式保存生效，停用方案可以保存新版本但不能启用。
- 孕周条件用周、天两个数值框录入；列表展示标准化的“29周0天”。
- 选择使用余额时，不阻断当前假别编辑；保存整套假期方案时，再校验年假/调休/病假额度规则是否已完成。

## 年假配置页

- 顶部保留 OEHR 的“年假生成规则、年假结转规则、年假结算规则”三阶段，不再拆成四个新的业务步骤。额度生成资格、额度计算与发放、补发规则作为“年假生成规则”内的信息组展示。
- 年假结算补齐交互：过期结算选择“按条件结算”时展开总失效额度判断条件；切换“不结算／全部结算”时收起条件，并即时显示当前规则结果。离职结算同样即时显示选择结果。
- “哪些员工可以获得年假额度”使用统一条件组件配置，例如人员状态为正式、连续工作满12个月且职位名称不包含司机。它只控制额度生成，不替代整套方案适用范围和休假申请资格。
- “标准配置、公式配置”只切换年假额度的计算方式，不切换额度生成资格。标准配置按 OEHR 现有字段分为“基本信息、额度配置规则、特殊规则、有效期、额度阶梯”；公式配置按 OEHR 现有字段分为“发放周期、发放规则、额度计算”。
- 标准配置继续保留 OEHR 的人员状态、最小单位、天转换小时数、小数位数、进位方式、年假规则、生成频率、计算精度、起算日期、年假周期、特殊规则、有效期和额度阶梯；公式配置继续保留归属年度、发放人员状态、发放方式、发放时间、标准额度、跨阶折算、计算公式及结果处理。本轮不合并或删除这些现有业务字段。
- 年假生成规则内部再分为三个纵向信息组：“哪些员工可以获得年假额度、额度如何计算与发放、是否需要特殊补发”。标准配置不使用左右并排卡片，每个 OEHR 信息组按纵向顺序完整展示；额度阶梯与跨年度补发分别归入第二、第三组，不再视觉粘连。
- 页面标题旁的问号集中说明“方案适用范围、额度生成资格、申请资格、申请时余额校验”四个控制层级，正文不再常驻展示产品解释卡片。
- 所有结构化条件根据字段类型提供判断方式：文本支持包含/不包含，枚举支持属于/不属于，数值和日期支持大小比较，并统一支持已填写/未填写。
- 国内年假普通生成使用公式配置：自然年归属、预发、每日发放，按工龄起算日匹配5天/10天/15天档位。
- 普通发放公式为：`取标准额度() × 取自然年实际在职天数(入职日期) ÷ 取自然年总天数()`；“预发＋每日”按截至当天的实际计算区间累计，结果四舍五入保留2位小数，不按8小时向下取整。
- 员工在当年跨越10年或20年工龄档位时，选择“按比例折算”：以跨档日为边界，原档、新档分别按各自实际在职日历天数占比折算后相加；跨档年度结果保留小数，不按整天向下取整。集团样例为2026年8月15日满10年，`(226÷365)×5＋(139÷365)×10≈6.90天`，以小时记账约为`55.23小时`。
- “额度跨阶折算方式”标签后提供可点击问号图标，右侧说明四种系统选项的实际含义和集团推荐值。
- “计算规则”标签后提供可点击问号图标，说明原公式应将`取自然年在职天数`替换为`取自然年实际在职天数`，并展示集团跨10年分段折算示例。
- “发放周期”“发放规则”“额度计算”分组标题后提供可点击问号图标，以“字段／系统实际含义／当前配置的含义”解释各字段。释义已对照OEHR公式配置实体、枚举和`FormulaCalculateAnnualLeaveServiceImpl`核验：人员状态用于计算任务筛选；预发＋每日计算至当天、实发＋每日计算至昨天；计算精度负责拆分公式执行区间；公式分段合计后再执行最终进位。
- “跨年度转正补发”作为预置补发能力，只保留启用开关，不再把触发时间、补算期间、归属年度、取整和生成后处理伪装成只有一个选项的下拉框。
- 业务页面统一表述为“员工转正后，首次符合‘哪些员工可以获得年假额度’的全部条件时补发”；转正时尚未满足连续工作满12个月等条件的，条件满足后再自动补发。
- 研发实现不能只在转正当天判断一次；转正、资格字段变化和额度任务都可以发起检查，最终通过员工、用工记录、入职年度和补发类型防止重复。
- 补发规则继承普通年假的标准额度阶梯、工龄匹配和跨档折算，但使用独立的补算期间与专项整天取整：回算入职日至入职年度12月31日，各段合计后按1整天向下取整，不足1天不生成。
- 启用补发规则时必须同时启用年假“余额转下期”；否则方案保存校验不通过。试算同时输入入职日期和资格满足日期，用于验证是否真正跨年以及额度转入年度。
- 专项额度生成后复用年假结转规则转至资格满足年度，因此业务归类首先是“年假发放”，结转只负责后续批次搬运和有效期管理。
- 原型在“跨年度转正补发规则说明”中补充“为什么归在年假生成”：补发负责判断是否应得、计算数量、确定归属年度并生成新额度；结转只处理已经存在的额度。示例统一为先生成归属2025年度的2天，再按结转规则转入2026年度。
- 结转规则：余额转下期，下一年12月31日失效，不允许再次结转，先到期先扣，销假恢复原批次和原失效日。
- 年假结转次数本轮不新增配置，继续沿用现有结转规则表达，待后续单独确认。
- 结算规则：普通过期和离职暂不结算；特殊岗位折现由审批确定获批时长，再交薪酬处理。
- 年假结算页默认展示“不结算”；只有业务人员主动选择“按条件结算”时才展开条件字段。
- 原型提供跨年度转正试算：可修改入职日期、资格满足日期和标准年假天数，实时查看是否跨年、折算、整天取整和结转结果。

## 调休假配置

- 页面与年假统一采用三个可点击页签：“调休生成规则、调休结转规则、调休结算规则”。本轮只调整信息分组与交互，不新增生命周期试算，也不改动 OEHR 原有字段和业务枚举。
- “调休生成规则”包含加班来源转换、生成比例和额度使用顺序；“调休结转规则”包含有效期、自动延期和到期处理；“调休结算规则”包含员工离职时的余额处理。
- 不再额外展示与页签重复的顶部说明卡和启用开关。哪些加班生成调休额度，仍由“加班转调休设置”决定。
- “加班费／调休假”属于加班方案的补偿方式配置，调休假页不重复展示成不可编辑字段。调休假页只承接补偿方式已经确定为“调休假”的加班时长，再配置来源转换、比例和有效期。
- “加班转调休设置”标签后的`规则说明`抽屉解释前置关系：提交加班申请时，加班方案可同时开放“加班费、调休假”供员工选择；按打卡自动计算加班时只能预设一种。选择加班费不进入调休额度，选择调休假才继续执行本页规则。
- 工作日、公休日、法定节假日加班在补偿方式选择调休假时按`1:1`生成调休额度；综合工时加班当前不转换。
- 每笔额度从对应加班日期起`6个月`后失效，不选择固定日期、考勤周期结束或永久有效，也不启用自动延期。
- 使用时按有效期先到期先扣；有效期相同时，先加班形成的额度先扣。销假按原扣减关系恢复至原加班来源额度并保留原失效日。
- 到期结算和离职结算均关闭；考勤不输出加班费金额。目标页面将离职处理表达为两个业务选项：“不结算，剩余调休余额失效”和“按加班来源折算为加班费时长”，当前选择前者；只有选择折算时才展开各来源和加班倍数。
- 页面配置和释义已对照OEHR调休配置组件、配置实体、日明细生成和有效期计算代码；现有系统的转换比例固定为`1:1`，有效期支持加班日起、固定日期、考勤周期结束和永久有效四类。

### 离职结算实现说明

- 现有OEHR离职结算没有整体“不结算”开关，且前端保存校验要求至少一个来源选择结算。要落地集团“全部不结算”，需要同步调整前端校验或由后端提供整体处理方式；该技术差异不在员工可见的业务配置文案中展示。

## 病假额度配置

- 仅当病假在休假配置中选择“按可用额度控制”时启用。
- 页面与年假、调休统一采用三个可点击页签：“病假生成规则、病假有效期规则、病假结算规则”。病假没有独立的结转业务，因此不为追求名称一致而新增结转逻辑。
- “病假生成规则”包含原有计算方式和额度使用顺序；“病假有效期规则”承接原有余额有效期配置；“病假结算规则”包含原有病假额度结算和离职结算。
- 不再额外展示与页签重复的顶部说明卡和启用开关，也不额外增加病假额度资格层。
- 额度生成规则保留 OEHR 的四种计算方式：固定额度、按考勤项目统计结果折算、自定义公式计算、手动导入；余额有效期保留固定日期、次年入职日期、按余额累积上限和永久有效。
- 未启用余额控制的病假，不要求配置病假额度页，也不阻止方案保存。
